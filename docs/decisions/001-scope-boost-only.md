# 001 范围：只做自动代练，积分计费，功能由后台 JSON 配置

日期：2026-10-23　状态：已确认（用户）

## 决定

1. **账号交易暂缓。** 角色筛选账号交易、批发、账号售后全部不做。第一阶段只做自动代练。
2. **计费用积分。** 用户购买积分包（Dujiao 商品）获得积分；创建任务时冻结，按实际完成量结算，剩余退回。不做按次权益套餐。积分只用于代练，不能提现、转账或换回钱包余额。
3. **每日自动计划不做。** 第一版只有手动发起。
4. **游戏、区服、代练功能全部由管理后台添加**，代码里不写死任何游戏。
5. **代练功能用 JSON 定义，前端自动生成界面。** 支持关卡目录（按章节分组）、通关 / 扫荡等模式分别定价、每个关卡的次数、条件显示、附加项、按时长计费。格式见 `docs/boost-feature-schema.md`。
6. **功能 JSON 的校验、报价、步骤生成只有一份实现**，后台保存、用户报价、服务端下单共用；前端价格一律不使用。

## 已定的细节

- 会员折扣在任务合计上算一次，向下取整；部分完成时同样先累计原价再打折，保证单调且全部完成时等于合计。
- 基础价（`base_points`）在任务开始执行后才收。
- 失败原因分类以服务端错误码表为准，Worker 上报的 `retryable` 只对未知错误码生效。
- 任务退回的积分按冻结时批次的逆序退回；批次已过期则退回即失效。
- 管理员重试失败任务 = 新建任务并重新冻结，原任务保持终态。
- 功能每次保存生成新版本；任务保存版本号和编译后的执行计划快照。
- 用户端字段错误只在改动或提交后显示；后台预览显示全部错误。

## 依据

用户 2026-10-23 反馈："先不弄账号交易这块，先把代练这个做好吧，后台可以添加游戏，以及对应的代练功能，或者说给一个格式化的 json 数据，让前端自动适配，生成代练功能的界面，包含关卡"；计费方式选择"积分"；每日计划选择"先去掉"。原型评审结论："基本符合要求"。
